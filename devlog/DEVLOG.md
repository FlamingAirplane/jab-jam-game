## Reflection

Reflection

We decided the core idea ourselves: a stone golem on a moon dungeon that can hold only one element at a time. Claude nudged us to keep the scope tight, and we cut the original 6-element skill-tree idea down to three elements (fire, water, earth) and one action: aim and fire. We rejected the “art first” path and told Claude gameplay came first, then let visuals follow once the loop felt good.

We also pushed back on deferring walls and columns — we wanted the arena broken up by cover, so we added them even though it was past the original M4 plan. We chose to install Blender and build a single golem model with element-specific variant parts rather than four separate high-poly models.

With another jam session we would finish the enemy roles: add the mage and healer, give each element a more distinct feel, and polish the sound and UI.

AI Use Disclosure

We used Claude Code in the build terminal to plan, code, and iterate. Claude Code wrote main.js, player.js, enemies.js, elements.js, fx.js, ui.js, tuning.js, and audio.js from our direction. It also wrote a headless Blender Python script (assets/make_golem.py) and exported assets/golem.glb. The floor mosaic texture, particle effects, and all sounds were generated by code at runtime (no downloaded files). We used reference images in context/references/ for mood and colour direction; none of them ship in the game. The devlog terminal used Claude Code (jam-cheap) to record our decisions.
